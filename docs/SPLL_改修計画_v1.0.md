# SPLL 改修計画 v1.0

**作成日:** 2026-11-17
**もとにする設計:** `docs/SPLL_管理画面1枚化・ステータススイッチ設計_v0.1.md`（以下「設計書」）、
`docs/SPLL_利用許諾契約書_v5.0.md`、`docs/SPLL_別紙_許諾作品通知書_v1.0.md`
**対象:** `spll_src/`（GAS 3プロジェクト）、`apps/public-web/`（AWS へ移す）、`scripts/`、`tests/`、`docs/`

---

## 1. 何を変えるか（要約）

| 領域 | 今 | 改修後 |
|---|---|---|
| 契約 | 作品ごとに1本の利用許諾契約（v4.1）。申込時に作品を選び、formrun の URL で条件を渡す | クリエーター1人1本の利用許諾契約（v5.0）＋作品ごとの別紙。各パートナーが当事者、表記は代表法人に固定 |
| 入口 | Cloud Run の公開サイトが GAS を呼んで申込・SPLL番号を作る | AWS（CloudFront + S3、Lambda）。入口では GAS を呼ばず、受付番号だけを formrun に渡す |
| 台帳のもと | formrun と CloudSign の Webhook を受けた時点で処理 | CloudSign の締結書類。Webhook は受信記録だけにして、定期実行で処理 |
| 作品の選択 | 申込の入口 | 専用ページ（トークン式）。申込は受付表に記録し、別紙は定期実行で作って CloudSign API で送る |
| 支払い | 対象外（入金未確認で停止のスイッチだけ） | 利用区分で前払い／後払い。前払いは入金CSVの取込で許諾が有効。同意待ち・入金待ちは3か月で失効 |
| 認証・バッジ | 審査 CLEARED の後 | 変えない（支払方法にかかわらず審査の後） |
| 管理画面 | 5タブ | 案件ボード1枚＋ステータススイッチ。設定・事務局運営は別パネル |

## 2. 進め方の方針

- **旧い流れを止めずに、新しい流れを横に作る。** 既存の v4.1 契約・案件はそのまま動かし続ける。新規の申込だけを新しい流れに切り替える（§6）。
- **状態遷移表（`12_license_state.gs`）を最初に直す。** 画面・バッチ・Webhook はすべて遷移表を通すので、ここを先に固めてテストで守る。
- **重い処理は定期実行へ。** 受信・受付は記録だけにする（設計書 §10）。
- **各段階でテストを足してから次へ。** `node scripts/test-all.js` が通らない状態で次の段階に進まない。
- **外部サービスの確認を先にやる。** CloudSign API のプラン、テンプレート、HTML→PDF の見た目は、作り込む前に試作で確かめる（P0）。

## 7. リスクと未決事項

| 項目 | 影響 | 対応 |
|---|---|---|
| CloudSign の API 送信が今のプランで使えない | 別紙を送れない | P0-3 で最初に確認。使えなければプラン変更 |
| HTML→PDF で見た目が再現できない | 別紙の作成時間が延びる、1日の作成数の上限 | P0-5 で決める。Google ドキュメント方式なら作成 1日1,500件 |
| メール 1日1,500通 | 1日 約500〜700件で上限 | 別紙の通知は CloudSign のメールに任せる。足りなければ別のメール送信手段 |
| スプレッドシートの量 | 案件1万件の手前で表示が遅くなる | 読み方の見直し（索引・キャッシュ）を P3 で入れておく |
| パートナーシップ契約の整備が遅れる | v5.0 の締結を始められない | P0-2 を最初に着手 |
| 入金CSVの形が決まらない | P5 が止まる | P0-6。決まるまでは手入力の照合を用意 |

**未決（あとで修正する前提のもの）**：SPLL番号の発番ルール（今は `SPLL-YYYYMM-####` で仮置き。現行の発番ルールに合わせて後で直す。振込名義の「数字10桁」と入金CSVの照合キーも、そのとき合わせて直す。照合は「SPLL番号から数字だけを取り出したもの」で行うので、桁数が変わってもコードは書き方の変更だけで済む）。

**未決（仮の値で進めるもの）**：後払いの支払期限（仮：各四半期末から30日）、専用ページのリンクの有効期限（仮：365日）、利用許諾契約の有効期間（仮：1年・自動更新）、一覧の既定の絞り込み（仮：要対応）。
