# SPLL クラウドサインフォーム項目設計 v2.0（簡素化版）

| 項目 | 内容 |
|---|---|
| 文書番号 | SPLL-SYS-FD-002 |
| 版数 | v2.0（v1.0を全面置換） |
| 根拠 | 分断・簡素化 実装計画（SPLL-SYS-RP-001）§8・§9 |
| 方針 | フォームは**「誰と契約するか」だけ**を取得する。契約条件は一切入力させない |

## 1. 費用決定の仕組み（フォームから条件入力を排除できる理由)

利用料は**契約形態（利用目的）× 選択した原作の構造**で自動決定される。

```text
ポータルで確定（申込時にLicense_Worksへスナップショット）
  利用目的（書籍/電子出版物/商品販売/…）→ Fee_Schedule の fee_model
    RATE … 売上 × 率（例 10%）
    FLAT … 契約単位の定額（例 16,500円／契約）
           ※複数原作を選んでも金額は変わらず、入金後に定額を
             対象原作の権利者間で分配する（既定＝原作数均等・手数料控除後）
  対象原作 → 原作数・クレジット・報告要否・分配先
```

- 申込完了時に**SPLL番号（license_id）**を発行し、費用・原作・条件は台帳スナップショットが正本
- 契約書はテンプレート固定＋スナップショットからの自動差込。**フォームでの再入力・確認入力は無し**
- 締結後にスナップショットと照合（条件不一致は自動有効化を停止）

## 2. フォーム構成（契約者区分で2フォーム）

ポータルの「契約者の区分」選択でフォームURLを切替える（Config: `FORM_URL_INDIVIDUAL` / `FORM_URL_CORPORATION`）。

### 2.1 個人・個人事業主フォーム（7項目）

| # | 項目 | 必須 | 備考 |
|---|---|:-:|---|
| 1 | 契約者区分 | ○ | 個人／個人事業主 |
| 2 | 氏名 | ○ | |
| 3 | 屋号・サークル名 | 任意 | |
| 4 | 住所 | ○ | |
| 5 | メールアドレス | ○ | CloudSign送信先 |
| 6 | 未成年確認 | ○ | 「私は18歳以上です」チェック（未成年は個別確認へ） |
| 7 | 契約内容確認 | ○ | §4の集約チェック |

### 2.2 法人フォーム（7項目）

| # | 項目 | 必須 |
|---|---|:-:|
| 1 | 契約者区分 | ○ |
| 2 | 法人名 | ○ |
| 3 | 所在地 | ○ |

| 5 | 契約締結者役職 | ○ |
| 6 | メールアドレス | ○ |
| 7 | 契約締結権限確認 | ○ |

## 3. v1.0から削除した項目

- フリガナ／メールアドレス確認欄／電話番号／生年月日／法人番号／担当部署・担当者電話
- 適格請求書発行事業者登録番号（必要時に経理側で取得）
- **制作・頒布予定情報の全て**（商品名・概要・形態・開始予定日・販売場所・価格・数量・地域・言語・URL・既公開情報）
  → 完成作品名・概要は**作品提出時**に取得（販売実績は経理側の独自運用で扱う）
- 条件の再入力（原作・料金・支払・報告・クレジット・特約）／多数の個別確認チェック

## 4. 確認チェック（2項目に集約）

1. **契約内容確認**：「申込内容及びSPLL利用許諾契約の内容を確認し、これに同意します。」
2. **契約締結権限確認**（法人）／**未成年確認**（個人）

反社・禁止事項・審査・是正・利用報告等の義務は契約本文で規定する。

## 5. hidden値（URL引継ぎ）

### 必須（3つ）

```text
license_id        SPLL番号（主参照番号）
application_ref   フォーム突合用参照番号
handoff_token     改変検知HMAC（受信時に検証）
```

### 表示・差込用（業務処理の正本にしない）

```text
usage_category / work_count / work_id_1..5 / work_title_1..5 / template_route
```

締結後の正本はLicense側スナップショット（License_Works／terms_snapshot）。hidden値の改変は
handoff検証＋締結後照合（TERMS_MISMATCH）で検出され、自動有効化されない。

## 6. formrun→SPLL連携（FORMRUN_FIELD_MAP）

workflow の ScriptProperties `FORMRUN_FIELD_MAP` にフォーム項目名→内部キーの対応をJSONで設定：

```json
{ "申込番号":"application_ref", "handoff":"handoff_token",
  "契約者区分":"party_type", "氏名":"party_name", "法人名":"company_name" }
```

受信時に契約者名・区分が**ライセンス台帳（License_Cases）へ自動反映**される（party_display_name / party_type）。

## 7. 例外案件

未成年・海外・利用目的「その他」・特約・原作数超過などは自動送信せず手動確認（MANUAL_REVIEW経路）。
管理コンソール「契約管理」タブのCloudSign例外対応パネルで手動送信・再申込を管理する。
