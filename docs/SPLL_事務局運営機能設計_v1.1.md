# SPLL TRPGライツ事務局 運営機能設計 v1.1

**文書番号:** SPLL-GOV-001  
**対象:** SPLLパートナーシップ契約（草案Ver008）  
**実装:** GAS③ 管理コンソール `事務局運営` タブ

> **v1.1（2026-08-13）改訂**：決議記録の不変性（§3.5）、議長資格のサーバー側検証（§2 第5条）、
> 出欠の画面記録（§5.1）、締結済み契約からの報告起票（§6.1）、日付のJST基準（§10）を追記。

## 1. 目的

パートナーシップ契約に基づくTRPGライツ事務局の会議体運営を、メール・個別ファイル・手作業の議事録管理から、SPLL管理コンソール上の一貫した証跡管理へ移行する。

対象は次の4領域。

1. 会議カレンダー・日時・議長・議事録
2. 議案・投票・決議
3. 利用許諾等の報告・資料請求記録
4. 四半期収益分配・費用負担・清算の記録

## 2. 契約条項との対応

| 契約 | システム機能 |
|---|---|
| 第4条 事務局の設置・権限 | 構成員、パートナー種別、議長資格、会議・議案管理 |
| 第5条 議長 | コアパートナーの議長資格、会議ごとの議長記録 |
| 第6条 決議 | 通常・特別・全員同意の自動判定、投票記録、議長裁量記録 |
| 第7条 パートナー種別変更 | `PARTNER_TYPE_CHANGE` を特別決議として固定 |
| 第9条3項 利用許諾報告 | 利用許諾対象・利用許諾料・利用目的の報告、翌月末期限管理 |
| 第9条4項 資料請求 | `material_request_status / note` で資料請求と対応記録 |
| 第10条 推奨業者 | 推奨業者選定・年次評価を議案／報告として管理 |
| 第11条 収益分配 | 四半期清算記録、分配基準、分配額、関連決議 |
| 第12条 費用負担 | 費用負担額・差引額・関連決議の記録 |
| 第14条 解散・清算 | 解散は全員同意。解散時清算を `DISSOLUTION` 清算記録で保持可能 |

## 3. 決議判定

### 通常決議

全有効構成員数を分母として、賛成が過半数の場合に成立。

### 特別決議

次の事項は自動的に `SPECIAL` とする。

- ライセンス料改定
- 収益分配変更
- パートナー種別変更

成立要件：

- 全有効構成員の3分の2以上が賛成
- かつ、コアパートナーに属する構成員1名以上が賛成

### 解散

`UNANIMOUS`。全有効構成員の賛成を必要とする。

### デッドロック

成立要件に達しない議案について、契約第6条2項に基づく議長裁量を記録可能。ただし、パートナー種別変更と解散は議長裁量によって成立させることができない。

### 3.5 決議記録の不変性

決議は「いつ・誰が・どの分母で」成立したかを後から動かせないことが要件となる。したがって次を守る。

| 事象 | 挙動 |
|---|---|
| 確定済み議案への投票 | 拒否（`DATA_CONFLICT`）。確定後に投票を受けると `computed_result` が上書きされ、記録済みの決議と食い違うため |
| 確定済み議案の編集 | 拒否。議案の中身・成立要件を後から差し替えると、記録された決議が別議案の決議になってしまう |
| 確定済み議案の再確定 | 拒否 |
| 構成員の入退任 | 過去の決議には影響しない。確定時の集計（分母・賛否・コア賛成）を `tally_json` にスナップショットし、確定済み議案の表示にはこれを使う（未確定議案のみ現在の構成員で判定） |
| 誤記録の訂正 | `admin_reopenSecretariatAgenda(agenda_id, reason)`。`LEGAL_ADMIN` のみ・**理由必須**・監査ログに旧結果とともに記録。投票そのものは保持したまま確定前へ戻す |

## 4. データモデル

- `Secretariat_Members`
- `Secretariat_Meetings`
- `Secretariat_Attendance`
- `Secretariat_Agendas`
- `Secretariat_Votes`
- `Secretariat_Reports`
- `Secretariat_Settlements`

初回利用時に `ensurePartnershipSheets_()` が不足シート・列を作成する。明示セットアップは `admin_setupPartnershipGovernance()`。

## 5. カレンダー

管理コンソールの月間カレンダーへ次の予定を重ねて表示する。

- 会議日時
- 報告期限
- 清算期限

会議にはGoogle Calendarのイベント作成URLを生成し、管理画面から「Googleカレンダーに追加」を選択できる。Calendar API権限は追加しない。
生成するURLは `dates=YYYYMMDDTHHMMSS/YYYYMMDDTHHMMSS`（秒まで必須）＋`ctz=Asia/Tokyo` とする。終了時刻が未設定または開始以前の場合は1時間として扱う。

期限超過（報告・清算）はカレンダー上で警告表示する。

### 5.1 出欠

会議ごとに構成員の出欠（出席／オンライン出席／欠席／陪席）を記録する。一覧は**未記録の構成員も含めて**返し、記録漏れがそのまま見えるようにする。会議一覧には出席・欠席の集計を添える。

パートナーシップ契約に定足数の定めはないため、出欠は決議の成立判定には用いない（決議の分母は常に全有効構成員）。

## 6. 報告管理

`LICENSE_AGREEMENT` は契約第9条3項の報告を想定する。

- 利用許諾対象TRPGライセンス
- 利用許諾料
- 利用目的の詳細
- 報告期限
- 提出日
- 根拠資料URL
- 他パートナーからの資料請求状況

締結日が入力された場合、期限は契約締結月の翌月末を自動算出する。

### 6.1 締結済み契約からの起票

管理画面「報告・清算」から契約IDを指定して `admin_createLicenseReportFromContract` を呼ぶと、
契約台帳（`Contracts` / `Contract_Works` / `terms_snapshot`）から報告対象・利用許諾料・利用目的を写し、
期限を締結月の翌月末に設定した下書きを作る。同じ契約からの二重起票は行わず、既存の報告を返す。

## 7. 清算管理

本機能は銀行入金消込・債権管理を行うFinanceシステムではない。

事務局として、パートナーへの四半期報告・収益分配・費用負担・支払済み記録を保持する。

- 対象期間
- パートナー
- SPLL収益総額
- 分配基準
- 分配額
- 費用負担額
- 差引額
- 報告／承認／支払状態
- 根拠資料URL
- 関連する決議議案ID

## 8. RBAC

閲覧は既存管理者ロールで可能。登録・更新・投票・決議確定は `LEGAL_ADMIN` / `OPERATIONS` に限定する。
初期セットアップは `SYSTEM_ADMIN` のみ、確定した決議の再開は `LEGAL_ADMIN` のみ。
（`SYSTEM_ADMIN` は `requireRole_` の仕様上すべてを通過する。）

議長は契約第5条により**コアパートナーに属する構成員**から選ぶ。コンテンツパートナーの構成員には議長資格を付与せず、
会議登録時にサーバー側で「有効な構成員であること」「議長資格があること」を検証する。

## 9. 監査証跡

構成員・会議・議案・投票・決議・報告・清算の主要更新は既存 `Events` へ記録する。

これにより、契約上の決議・報告・清算について、誰がいつ何を登録・確定したかを追跡できる。

## 10. 日付とタイムゾーン

事務局の期限・当日判定・カレンダーはすべて**JST基準**とする。

GASのスクリプトタイムゾーンはJSTだが `Date.prototype.toISOString()` はUTCを返すため、
`new Date(...).toISOString().slice(0,10)` で日付を作ると**1日ずれる**（JST 0:00〜9:00 は前日になる）。
したがって次を守る。

- 当日・現在時刻：`Utilities.formatDate(new Date(), 'JST', ...)`
- 月末計算（報告期限）：`Date.UTC(y, m+1, 0)` でUTC固定に組み立ててから日付を取り出す
- 期限超過の判定：JSTの当日文字列と `due_date` を文字列比較する

## 11. 性能

一覧・カレンダーは議案ごとにシートを読み直さず、`partnershipContext_()` で
`Secretariat_Agendas` / `Secretariat_Members` / `Secretariat_Votes` / `Secretariat_Attendance` を
1回だけ読み、その結果を使って評価・集計する。スプレッドシート読み取りはGASで最も高コストな操作のため。
